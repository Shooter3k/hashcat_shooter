========================================================================
 HOW TO COMPILE THIS HASHCAT BUILD (Windows / MSYS2 MinGW64)
========================================================================

This is hashcat_shooter based on the latest GitHub master, with the local
beta improvements ported forward. It is compiled on Windows using the MSYS2
MinGW64 toolchain. The steps below work with a fresh clone in any directory.

------------------------------------------------------------------------
 PREREQUISITES (one-time)
------------------------------------------------------------------------
- Install MSYS2 from https://www.msys2.org/ and finish its initial update.
- Open the "MSYS2 MINGW64" shell. Do not use the plain MSYS, UCRT64, MINGW32,
  or CLANG shells: the package names and compiler target below are for
  64-bit MinGW Windows builds.
- Update MSYS2, restarting the shell and repeating the command if requested:

    pacman -Syu

- Install the compiler, build tools, and the OpenSSL 3 development files used
  by the mdxfind bridge:

    pacman -S --needed \
      mingw-w64-x86_64-gcc \
      mingw-w64-x86_64-make \
      mingw-w64-x86_64-openssl \
      make git

- Clone this repository, not the upstream hashcat repository:

    git clone https://github.com/Shooter3k/hashcat_shooter.git
    cd hashcat_shooter

  OpenSSL is linked statically into bridge_mdxfind.dll. Builders need the
  package above, but users of the resulting Windows build do not need a
  separate OpenSSL DLL.

- CUDA is loaded at RUN time (not needed to compile). The compiled .exe
  finds CUDA via the NVIDIA driver at runtime.

------------------------------------------------------------------------
 BUILD (the normal way - from the MSYS2 MINGW64 shell)
------------------------------------------------------------------------
From the repository directory, run:

    make PRODUCTION=1 -j

Notes:
- make PRODUCTION=1 -j builds using all CPU cores and embeds the dated shooter
  version instead of a dirty-tree Git description.
- A zero exit status means the build succeeded. For a failure, diagnose the
  first error in the complete output rather than only the final message.
- IMPORTANT: after editing include/types.h, use the CLEAN REBUILD below.
  This Makefile does not track every header dependency; an incremental build
  can mix incompatible structure layouts and produce an access-violation
  crash. Editing only a .c file can use the normal incremental build.

------------------------------------------------------------------------
 BUILD (optional - launch the build from PowerShell)
------------------------------------------------------------------------
Set these two paths for your machine. The default MSYS2 installation directory
is C:\msys64; the repository can be anywhere:

    $MsysRoot = 'C:\msys64'
    $Repo = 'C:\path\to\hashcat_shooter'
    $RepoMsys = (& "$MsysRoot\usr\bin\cygpath.exe" -u $Repo).Trim()
    $env:MSYSTEM = 'MINGW64'
    & "$MsysRoot\usr\bin\bash.exe" -lc "cd '$RepoMsys' && make PRODUCTION=1 -j"

The cygpath conversion makes this work for repositories on any drive.

------------------------------------------------------------------------
 CLEAN REBUILD (from scratch)
------------------------------------------------------------------------
If a build behaves oddly or you want a guaranteed-fresh binary, run this from
the repository directory in the MSYS2 MINGW64 shell:

    make clean && make PRODUCTION=1 -j

WARNING: this repository's make clean target removes more than obj/ artifacts.
It also removes the built executable and runtime files in the source root,
including *.pid, *.log, *.induct directories, and *.outfiles directories.
Move any runtime/session data you need to keep out of the source root before
running it. Normal .restore files are not removed by make clean.

------------------------------------------------------------------------
 RUNNING WHAT YOU BUILT (quick sanity check)
------------------------------------------------------------------------
Run from PowerShell. Set the same paths used above, put the MinGW64 runtime
DLLs on PATH, and run from the repository directory:

    $MsysRoot = 'C:\msys64'
    $Repo = 'C:\path\to\hashcat_shooter'
    $env:PATH = "$MsysRoot\mingw64\bin;$env:PATH"
    Set-Location $Repo
    .\hashcat.exe --version
    .\hashcat.exe -I
    .\hashcat.exe --help  # confirm mode 1 says Combination and official mode 12 is present

The runtime cache is written beside hashcat.exe as:
    hashcat.autotune-cache beside hashcat.exe

It is generated automatically and ignored by Git. A rebuilt hashcat.exe gets
a new build identifier, so old entries are not reused.

IMPORTANT: Run the .exe from PowerShell, NOT from inside the MSYS2 bash
shell. Launching it from MSYS2 bash strips the Windows PATH and it will
report "No CUDA platform found".

------------------------------------------------------------------------
TROUBLESHOOTING
------------------------------------------------------------------------
- "fatal error: openssl/des.h: No such file or directory" (or another
  openssl/*.h header):
    The mdxfind bridge's build dependency is missing from the active MinGW64
    environment. Open the MSYS2 MINGW64 shell and run:
        pacman -S --needed mingw-w64-x86_64-openssl
    Confirm that `command -v gcc` prints /mingw64/bin/gcc, then rerun make.

- "No CUDA platform found" at runtime:
    You launched from MSYS2 bash. Run it from PowerShell instead (see above).

- Exit code 1 after a crack run:
    Normal - it just means not every hash was cracked. Not an error.

- Exit code -1073741819:
    That is a crash (access violation), not a normal exit.

- "Permission denied" for the `-o` file:
    This build retries transient Windows access and sharing failures every
    250 ms for up to 5 seconds. If the file stays unavailable, later results
    still make one immediate write attempt without repeatedly stalling the
    cracking threads; another timed retry window is allowed after 30 seconds.
    Close the program holding the file or correct its permissions if the final
    error remains. If `--potfile-disable` is in use, do not ignore that final
    error: results recovered while the file remains unavailable cannot be
    appended to `-o`.

- Build says nothing rebuilt / exe timestamp doesn't change:
    make detected no changed source files, so there was nothing to do.
    That is correct. Use the CLEAN REBUILD above to force a full rebuild.

- Spurious ">: empty file." keyspace errors on tiny test wordlists:
    Delete the stale dictionary cache and rerun:
        Remove-Item "$Repo\hashcat.dictstat2" -Force
