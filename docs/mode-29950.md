# phpBB3 bcrypt-over-phpass legacy rehashes

Shooter modes `29950` and `29951` process phpBB3 password records whose old
phpass checksum was rehashed through bcrypt. No extraction script is required
for the original database value.

| Mode | Construction |
| --- | --- |
| `29950` | `bcrypt(phpass($pass))` |
| `29951` | `bcrypt(phpass(md5($pass)))` |

Mode 29951 is intentionally separate. Use it only for records known to use
the MD5-prehash migration path; hashcat does not guess between the two
constructions.

## Accepted formats

The preferred input is the exact original phpBB value:

```text
$H\2y$7RsqOrLNk$10\vw31ldi5VPlyG2t5HxqIKe$yFv5dvOFakbr/GBBC0oyfIGMOkSD1dq
```

The parser also accepts an extracted representation:

```text
$2y$10$vw31ldi5VPlyG2t5HxqIKeyFv5dvOFakbr/GBBC0oyfIGMOkSD1dq:7RsqOrLNk
```

The fields in the original form are:

```text
$H\ 2y $ 7 RsqOrLNk $ 10 \ vw31ldi5VPlyG2t5HxqIKe $ yFv5dvOFakbr/GBBC0oyfIGMOkSD1dq
     |    | |          |     |                      |
     |    | |          |     |                      +-- bcrypt digest (31 chars)
     |    | |          |     +------------------------- bcrypt salt (22 chars)
     |    | |          +------------------------------- bcrypt cost
     |    | +------------------------------------------ phpass salt (8 chars)
     |    +-------------------------------------------- phpass count character
     +------------------------------------------------- bcrypt variant
```

The phpass count character is an index into:

```text
./0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz
```

Its index is the base-2 iteration exponent. In the supplied sample, `7` is at
index 9, so the phpass stage uses `2^9 = 512` iterations. Shooter accepts
phpass count exponents 7 through 30 and bcrypt costs 04 through 31.

## What is hashed

For mode 29950, the GPU computes the normal phpBB3 portable phpass operation
using the candidate, phpass count, and phpass salt. It then encodes only the
16-byte result into the 22-character phpass checksum. That checksum—not the
`$H$` signature, count character, or salt—is the password supplied to bcrypt.

For the supplied plaintext `123456`:

```text
phpass checksum: cmD0qyV8sv/3sGcLRo8D31
bcrypt input:    cmD0qyV8sv/3sGcLRo8D31
```

Reattaching the phpBB fields demonstrates the intermediate value:

```text
$H$7RsqOrLNkcmD0qyV8sv/3sGcLRo8D31:123456
```

Mode 29951 first converts `md5($pass)` to its 32-character lowercase hex
text, then runs the same phpass and bcrypt stages.

## Windows usage

Run mode 29950 for the standard legacy rehash:

```powershell
hashcat.exe -m 29950 -a 0 hashes.txt wordlist.txt
```

Run the separately selected MD5-prehash variant only when appropriate:

```powershell
hashcat.exe -m 29951 -a 0 hashes.txt wordlist.txt
```

Standard rules and attack modes remain available, for example:

```powershell
hashcat.exe -m 29950 -a 0 hashes.txt wordlist.txt -r rules\best64.rule
```

Both modes are pure kernels because each candidate requires two staged
variable-cost algorithms. Passing `-O` is accepted and falls back to the pure
kernel. Candidate plaintexts up to 256 bytes are supported; the outer bcrypt
stage always receives the fixed 22-character phpass checksum.

The modes cap autotuning at `Accel:8` and `Loops:8`. Hashcat's normal staged
autotuner measures the first loop, which is inexpensive phpass MD5 here; an
uncapped result can therefore create a very large, long-running bcrypt launch.
The cap was measured on the target RTX 4090 system and keeps status, runtime,
quit, and checkpoint controls responsive without reducing completed-candidate
throughput. Existing cache entries with the old tuning range do not match the
new cache key and are ignored automatically.

## Performance and scheduling

Every candidate must complete the selected phpass iteration count and then
the bcrypt cost. This is inherently much slower than cracking either an MD5
or an ordinary phpass hash alone. Both stages use the normal hashcat
multi-device scheduler, so the modes work across the twelve-RTX-4090 setup,
with rules, status, restore, potfiles, and outfiles.

Different phpass salts, count characters, bcrypt salts, variants, and costs
can coexist in one hash file. Invalid count characters, out-of-range costs,
bad bcrypt base64, and malformed separators are rejected during parsing.

Use these modes only for password records and systems you own or are
explicitly authorized to audit.
